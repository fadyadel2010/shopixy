# Carrier credential configuration and connection UI — 2026-10-15

## Scope and outcome

Bosta, Aramex, DHL Express MyDHL REST and Mylerz configuration/connectivity only. Manual remains credential-free. FedEx's schema, endpoints, catalog and qualification are not changed. No shipment, label, pickup creation, cancellation, COD, accounting, activation, service enablement, schema change, migration or history repair was performed.

The four cards now separate **Save** from **Test Connection**. Save uses the existing tenant/carrier-bound Data Protection encryption, retains blank saved secrets and merges encrypted extra settings. Test reads saved credentials/environment and calls the real adapter. Presence-only DTO metadata supports masked placeholders and reloads. Neither action changes integration enablement, service policies or account activation.

## Root causes and reproduction

1. Bosta capability metadata incorrectly made webhook authorization, COD collection currency and business pickup-location ID authentication prerequisites. On the actual `/ecommerce/shipping-methods` page, entering only a synthetic key and clicking Save dispatched **zero requests**; the browser identified those three unrelated required fields. Browser validation also produced unfocusable-control errors for collapsed required settings.
2. Both buttons required reentry of all credentials and sent the same save-and-validate command. The original Test action overwrote configuration and enabled it; Save disabled it. No saved-field metadata allowed masked values to satisfy validation after reload. Separate environment selection and the form's independently defaulted sandbox checkbox could disagree.
3. Save did not synchronize the account's active credential reference/environment with encrypted runtime configuration. Merchant status also depended on operational readiness, conflating authentication with activation/geography.
4. DHL validation returned success from local nonempty fields without provider I/O. Bosta's cities catalog check admitted any HTTP200 without validating an authenticated business response. Mylerz's connection handler was disabled despite the existing public token client.
5. The standard API error result filter wraps refused command DTOs in `Details`, serialized as **`data`**, preserving PascalCase dictionary keys. The frontend read only top-level `failureCode`/`blockers`, losing actionable codes and displaying “Invalid request.” The fix admits raw, `data` and older `details` envelopes without changing infrastructure.
6. Historical test records did not establish which authentication operation produced success. Versioned existing audit evidence now distinguishes current authenticated tests from old presence-only/catalog checks. Latest records, credential reference, environment and configuration fingerprints must agree. A fresh failure replaces success; slow superseded/configuration-changed results cannot restore it.
