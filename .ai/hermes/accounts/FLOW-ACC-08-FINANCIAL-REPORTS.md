## 0. Critical Orientation: Reports Are Projections, Not Owners

The single most important architectural fact for this domain:

**A. Financial Reports = READ-ONLY PROJECTIONS of the General Ledger.**

- There is no `FinancialReport` aggregate, no report table, no report store.
- The entire report surface is produced by ONE service — `FinancialReportService` — which reads `LedgerEntries` / `LedgerAccounts` (and transitively `JournalEntry`) and computes in memory / SQL aggregation.
- Every report model (`TrialBalanceReport`, `ProfitAndLossReport`, `BalanceSheetReport`, `CashFlowReport`, `GeneralLedgerReport`, `ClearingAgingReport`, `AccountSummary`) is a **computed DTO**, materialized per request from the live ledger. See `FinancialReportService.cs:24` (class declaration) and each per-report method.

**B. The General Ledger is the single financial source of truth.** Reports never own balances; they derive them. See §8.

> Status legend used throughout: ✅ Implemented · 🟡 Partially Implemented · ❌ NOT IMPLEMENTED.

## 1. Executive Summary

**What is a Financial Report?**
A read-only, point-in-time projection of the immutable General Ledger, computed from `LedgerEntries` aggregated by `Account`, filtered by journal status (`Posted`/`Reversed`) and date. Implemented as computed DTOs returned by `FinancialReportService` — `FinancialReportService.cs:41,123,193,277,375,460,556`.

**Who owns it?**
- **Runtime/compute ownership:** `FinancialReportService` (`IFinancialReportService`) — the only report builder. `FinancialReportService.cs:24`.
- **Source-of-truth ownership:** the **General Ledger** (written only by `FinancialPostingService`, gated by `LedgerMutationScope`). Reports have no write authority. See FLOW-ACC-04.
- **HTTP ownership:** `FinancialReportsController` — thin pass-through that injects tenant, normalizes dates, and calls the service. `FinancialReportsController.cs:19`.

**What does it own?**
- Query orchestration (date range, account selection, aggregation).
- Totals, subtotals, ratios, balance checks (`IsBalanced`, `Variance`, `CurrentRatio`, `DebtToEquityRatio`) — all computed in the report model, NOT stored.
- Export rendering (handled client-side in the browser, §13).

**What does it NOT own?**
- It does NOT own account balances (those live on `Account.CurrentBalance`, maintained by the posting engine — `Account.cs:96-122`).
- It does NOT own the journal/ledger (immutable, owned by posting engine).
- It does NOT own business data (SalesInvoices, Customers, Products, etc.) — access is forbidden by contract + CI test.

**What is the financial source of truth?**
The **immutable General Ledger**: `JournalEntry` (`LedgerJournalEntries`) + `LedgerEntry` (`LedgerLines`) referencing `Account` (`LedgerAccounts`), filtered to `Status == Posted || Reversed`. Every report reads `LedgerEntries` and joins `JournalEntry` for status/date. Example: `FinancialReportService.cs:56-80` (Trial Balance), `:216-242` (P&L), `:297-321` (Balance Sheet), `:476-518` (Clearing Aging).

## 5. Lifecycle

Implemented stages (traced):

- **Generate** ✅ Every request recomputes from the ledger. There is no persisted report. `FinancialReportService.cs:41-117` (TB), `:123-187` (GL), `:193-271` (P&L), `:277-369` (BS), `:375-454` (CF).
- **Calculate** ✅ Done in two layers: (a) SQL `GroupBy`/aggregate in `FinancialReportService`; (b) in-memory totals in the report DTO (`TotalDebits`, `NetProfit`, `TotalAssets`, etc.). E.g. `FinancialReportService.cs:63-80` + `TrialBalanceReport.cs:20-35`.
- **Read** ✅ `AsNoTracking()` reads inside a `RepeatableRead` transaction (see §10). `FinancialReportService.cs:57` (`AsNoTracking`), `:650-658` (`BeginConsistentReadTransactionAsync`).
- **Export** ✅ Client-side only (§13).
- **Refresh** ✅ Implicit — every HTTP call re-reads the live ledger; no stale snapshot to refresh.
- **Cache** 🟡 NOT for reports. `GetOrCreateCachedAsync` is a no-op wrapper that always recomputes (`FinancialReportsController.cs:279-287`): comment "Financial reporting is recomputed from the ledger for every request." Only the FE dashboard has a 30s `BoundedTTLCache` (`financialReportsApi.js:17-97,126-145`).
- **Snapshot** ❌ NOT IMPLEMENTED for reports. (The `Snapshot` type found in `tools/SIDmsgRunner` is an *event-artifact* test harness for stock/accounting outbox reconciliation — unrelated to financial reporting.)
- **Archive** ❌ NOT IMPLEMENTED. No report retention.

## 7. Report Behavior

Reverse-engineered per report:

**Trial Balance** (`FinancialReportService.cs:41-117`)
- Groups `LedgerEntries` by `AccountId, AccountCode, Name, AccountType` within `[from,to]` and `Status ∈ {Posted,Reversed}`.
- `NormalBalance` derived in-memory from `AccountType` (`GetNormalBalance()`); `Balance = Debits−Credits` (debit-normal) or inverse.
- `IsBalanced` ⇔ `|TotalDebits − TotalCredits| < 0.01`; logs warning if unbalanced (`:109-114`).
- Front-end shows a BALANCED/UNBALANCED banner + variance. `TreasuryTrialBalance.jsx:178-205`.

**Profit & Loss** (`FinancialReportService.cs:193-271`)
- Filters `AccountType ∈ {Revenue, CostOfGoodsSold, Expense}`.
- Amount per account: Revenue = `Credits−Debits`; Expense/COGS = `Debits−Credits`.
- Totals: `GrossProfit = Revenue − COGS`; `NetProfit = GrossProfit − Expenses`; margins computed. `ProfitAndLossReport.cs:39-73`.
- **Reads Ledger, NOT an Expenses business table** (see §16).

**Balance Sheet** (`FinancialReportService.cs:277-369`)
- Filters `AccountType ∈ {Asset, Liability, Equity}`; aggregates `JournalDate <= asOfDate`.
- Lines with `Balance == 0` are dropped (`:333`).
- `IsCurrent` derived from `AccountCode` convention (1000-1499 current assets; 2000-2499 current liabilities) — `IsCurrent()` `:640-648`.
- Ratios: `CurrentRatio` (current assets / current liabilities) and `DebtToEquityRatio`. `BalanceSheetReport.cs:73-80`.
- `IsBalanced` ⇔ `|Assets − (Liabilities+Equity)| < 0.01`.

**Cash Flow** (indirect method) (`FinancialReportService.cs:375-454`)
- Calls `GetProfitAndLossAsync` for `NetProfit`.
- Computes opening/closing **cash** as balances of accounts whose `AccountCode` starts with `"10"` (`:394-400`).
- Working-capital adjustments from code-prefix balance deltas: `12*` (AR), `13*` (Inventory), `20*` (AP). Increase in AR/Inventory = cash outflow; increase in AP = inflow (`:406-439`).
- `NonCashAdjustments`, `InvestingActivities`, `FinancingActivities` are returned **empty** (future/placeholder). `Reconciles` checks `OpeningCash + NetCashChange == ClosingCash` (`CashFlowReport.cs:96`).

**General Ledger** (per account) (`FinancialReportService.cs:123-187`)
- Opening balance = sum of ledger entries `< fromDate` (`GetAccountBalanceAsOfAsync`, `:145,601-635`).
- Entries in range, ordered by `JournalDate` then `LineNumber`, each with `BalanceAfter`.
- Closing balance = sum `<= toDate` (`:173`).

**Account Summary** (`FinancialReportService.cs:556-592`)
- All `LedgerAccounts` + current balance from `GetAccountBalancesAsOfAsync(DateTime.UtcNow)`.

**Opening / Closing Balance** ✅ Implemented via point-in-time ledger sum (`GetAccountBalanceAsOfAsync`, `:601-635`). No retained-earnings / profit-carry-forward account is computed — the Equity section is whatever ledger balances exist for `AccountType.Equity`. **Retained Earnings / Profit Carry Forward = NOT IMPLEMENTED** (no code references found).

**Filtering** 🟡 implicit only (status, date, type, code prefix). **Grouping** 🟡 fixed by type. **Totals** ✅ computed in DTOs. **Pagination** ❌ NOT IMPLEMENTED (controller returns full lists; `ReportsController` has a `MaxTabularReportItems` cap but that's a different, excluded controller). **Drill-down** ✅ Trial Balance → GL via `navigate('/treasury/general-ledger?accountId=...')` (`TreasuryTrialBalance.jsx:268`). **Multi-currency** ❌ NOT IMPLEMENTED (§3).

## 8. Financial Behavior

- **Financial Truth:** The immutable General Ledger (`JournalEntry` + `LedgerEntry`) is the single source of truth. `FinancialReportService.cs:19` ("Ledger is the ONLY source of truth").
- **Ledger Source:** `LedgerEntries` table is the primary read target for every report.
- **Journal Source:** `JournalEntry` is joined for `Status`, `JournalDate`, `JournalNumber`, `SourceType`, `SourceReference`. Reports never read journals without the `Posted`/`Reversed` filter (`:59-62` etc.).
- **Balance Calculation:** `ComputeBalance(type, debits, credits)`:
  - Debit-normal (Asset, Expense, COGS): `Debits − Credits`
  - Credit-normal (Liability, Equity, Revenue): `Credits − Debits`
  - `FinancialReportService.cs:701-706`; `AccountTypeExtensions.cs:13-25`; `Account.cs:112-122` (`ApplyEntry`).
- **Debit / Credit:** Stored per line on `LedgerEntry.DebitAmount`/`CreditAmount` (`decimal(18,4)`); exactly one is > 0 (`LedgerEntry.cs:10-14`).
- **Opening Balance:** Point-in-time sum of all posted/reversed entries before the date (`GetAccountBalanceAsOfAsync`, `:601-635`).
- **Closing Balance:** Point-in-time sum through the date (same helper).
- **Retained Earnings / Profit Carry Forward:** ❌ NOT IMPLEMENTED. No equity roll-forward, no closing-entry generation. Equity section = raw `AccountType.Equity` ledger balances.
- **Read Model Strategy:** *Recompute-on-read projection.* No materialized view, no stored read model, no cache of report output. Each request re-aggregates `LedgerEntries` via SQL `GroupBy` then finishes totals in memory. `FinancialReportService.cs:56-80,216-242,297-321`.

## 9. Constraints

Implementation-backed rules:

1. **Tenant Isolation — ENFORCED.** Every query filters `l.TenantId == tenantId` (`FinancialReportService.cs:58,150,218,299,478,562`). Controller uses `ITenantContext.RequiredTenantId` (`FinancialReportsController.cs:40`). Cross-tenant leak impossible at query level.
2. **Ledger-Only Source — ENFORCED (CI-block).** `FinancialReportService : ILedgerOnlyService` (`FinancialReportService.cs:24`). `ForbiddenBusinessDbSets.Names` lists SalesInvoices, PurchaseInvoices, Customers, Suppliers, Products, StockMovements, CashboxTransactions, etc. (`ForbiddenBusinessDbSets.cs:17-56`). `LedgerIsolationTests` fails CI on any violation (`LedgerIsolationTests.cs:29-86,93-104,111+`).
3. **Balanced Journal Requirement — inherited, not re-checked by reports.** Reports assume the ledger is balanced (enforced at post time by `FinancialPostingService`). Reports *verify* their own output via `IsBalanced`/`Variance` but do not mutate. `TrialBalanceReport.cs:30`; `BalanceSheetReport.cs:59`.
4. **Date Validation — UTC normalization.** Controller forces `DateTimeKind.Utc` before querying (`NormalizeToUtc`, `FinancialReportsController.cs:46-54`) because PostgreSQL `timestamptz` requires UTC. No range-order validation (no `from<=to` guard) — **NOT IMPLEMENTED**.
5. **Period Validation — NOT IMPLEMENTED** (no closed-period / fiscal-period lock; reports read any date range).
6. **Report Consistency — eventual-at-read.** Because reports recompute from the live ledger inside a `RepeatableRead` transaction, a single report is internally consistent; cross-report consistency depends on the ledger not changing mid-flight (see §10).
7. **Ledger Consistency — guaranteed by posting engine**, not reports. Reports are read-only consumers.

## 10. SQL Transactions

- **Read live?** ✅ YES. All reports read live `LedgerEntries`/`LedgerAccounts` every call; no snapshot/materialized view. `FinancialReportService` methods (`:56,148,216,297,476,565`).
- **Read snapshot?** ❌ NO.
- **Read materialized views?** ❌ NO.
- **Use transactions?** ✅ YES — a read transaction is opened per report. `BeginConsistentReadTransactionAsync` (`FinancialReportService.cs:650-658`) calls `BeginTransactionAsync(IsolationLevel.RepeatableRead, ...)` when relational and no outer tx exists.
- **Isolation level:** `RepeatableRead`. Rationale: a consistent, non-changing view of the ledger during aggregation.
- **Consistency guarantees:** Within a single report call, `RepeatableRead` prevents phantom/non-repeatable reads so totals are internally consistent. No cross-report distributed tx.
- **Caching:** ❌ Server-side report caching is disabled by design — `GetOrCreateCachedAsync` always invokes the factory (`FinancialReportsController.cs:279-287`). A 30-second **front-end** `BoundedTTLCache` exists for the dashboard endpoint only (`financialReportsApi.js:14,97,126-145`).

---

## 11. Events

- **Refresh Events:** ❌ NONE. No report refresh/publish events.
- **Projection Updates:** ❌ NONE. Reports are not projections fed by an event stream; they query the ledger directly.
- **Snapshot Generation:** ❌ NONE for reports.
- **Cache Invalidation:** ❌ NONE server-side; FE cache expires by TTL (`financialReportsApi.js:66-86`).

> Note: The broader system DOES use events/outbox (`AccountingOutboxProcessor`, `IEventPublisher`) for *posting*, but those drive the **ledger write path**, not report generation. Reports are decoupled from that pipeline.

## 13. Browser Test Specification

Front-end surface: `PointOfSale.Web/src/pages/treasury/*.jsx` + `financialReportsApi.js`. Export libs: `xlsx`, `jspdf`, `jspdf-autotable`.

**Scenarios**
1. Trial Balance loads with date range → table of accounts with Debits/Credits/Balance.
2. P&L loads → Revenue/COGS/Expense sections + Gross Profit + Net Profit.
3. Balance Sheet loads (asOf) → Assets/Liabilities/Equity + Current Ratio + Deb/Equity.
4. Cash Flow loads → Opening/Closing cash, Net Profit, working-capital adjustments, Reconciles flag.
5. General Ledger (per account) → opening, entries w/ running `BalanceAfter`, closing.
6. Drill-down: Trial Balance row "Ledger" button → navigates to GL for that `accountId`.
7. Export: each report page Excel + PDF buttons produce a downloadable file.

**Assertions**
- TB: `isBalanced == true` and `|totalDebits − totalCredits| < 0.01` (banner green).
- BS: `isBalanced == true` (`assets == liabilities + equity`).
- CF: `reconciles == true` (`openingCash + netCashChange == closingCash`).
- GL: `closingBalance == openingBalance + Σ(debits − credits)`.
- Every line `balance` matches `debit/credit` math per `NormalBalance`.
- `generatedAtUtc` present; `tenantId` matches session.

**Negative Cases**
- Empty period → report returns zero lines, `isBalanced` true (0 == 0), no crash.
- Unknown `accountId` (GL) → controller returns **404** "Requested account was not found." (`FinancialReportsController.cs:104-112`).
- Unauthorized (no token) → `[Authorize]` → 401.
- `from`/`to` omitted → DateTime default (UTC now) — verify no 500.
- Currency: confirm report payload has **no currency field** (display formatting only).

**Totals**
- TB totals row = Σ lines; variance displayed when unbalanced.
- P&L: `TotalRevenue − COGS = GrossProfit`; `GrossProfit − Expenses = NetProfit`.
- BS: sum of each section equals `TotalAssets`/`TotalLiabilities`/`TotalEquity`.

**Filtering**
- Date filter respected: entries outside `[from,to]` excluded (verify by seeding a posted journal outside range).
- Status filter: a `Reversed` journal is included; a `Draft` (non-posted) journal is excluded (only `Posted`/`Reversed` qualify — `FinancialReportService.cs:59`).

**Consistency / Cross-Report Validation**
- TB `TotalDebits` == TB `TotalCredits` (double-entry holds across all reports).
- P&L `NetProfit` equals the change in `AccountType.Equity` (net of any equity postings) — approximate check, since no retained-earnings roll-up exists.
- BS `TotalAssets` == `TotalLiabilities + TotalEquity` at `asOf`.
- CF `NetProfit` sourced from same ledger as P&L (same `NetProfit` value).

**Export Validation**
- Excel: header row + one row per line + TOTALS row present (`TreasuryTrialBalance.jsx:60-67`).
- PDF: title, period, auto-table body, TOTALS footer, BALANCED/UNBALANCED stamp.
- File names follow pattern `TrialBalance_YYYY-MM-DD_YYYY-MM-DD.xlsx` / `.pdf` (`:71,113`).

## 15. Canonical Pattern

```
JournalEntries (immutable, Posted/Reversed)
        ↓  written ONLY by FinancialPostingService (ledger aggregate owner)
LedgerEntries (debit/credit lines, BalanceAfter per line)
        ↓  read by
FinancialReportService  (IFinancialReportService, ILedgerOnlyService)
        ↓  SQL GroupBy + in-memory balance math, inside RepeatableRead
Computed Report DTOs (TrialBalance / P&L / BalanceSheet / CashFlow / GL / ClearingAging)
        ↓  HTTP (FinancialReportsController, tenant-scoped)
Browser (Treasury*.jsx) → client-side Excel/PDF export
```

Reports are **stateless projections** of the ledger. They own no data, enforce no balances (they only *verify*), and recompute on every read. The ledger is the single financial truth; reports are its read side.

## 17. Final Architecture Conclusion

- **Reporting Authority:** `FinancialReportService` (the sole `IFinancialReportService` implementation), exposed via `FinancialReportsController`. It is a read-only projection engine, not an owner.
- **Financial Truth:** The immutable General Ledger (`JournalEntry` + `LedgerEntry`), written only by `FinancialPostingService`. Reports are downstream consumers.
- **Projection Strategy:** Recompute-on-read. SQL `GroupBy` aggregation + in-memory balance math, no stored read models, no snapshots, no materialized views.
- **Runtime:** Browser → Controller (tenant + UTC normalize) → `FinancialReportService` (RepeatableRead tx) → live `LedgerEntries`/`Account` → computed DTO → Browser → client-side Excel/PDF export.
- **Aggregate Ownership:** Ledger aggregate = posting engine. Reports = stateless side; no `FinancialReport` aggregate exists.
- **Caching Strategy:** Server-side caching explicitly disabled for reports (recompute every call). Only a 30s front-end dashboard TTL cache.
- **Integrity Strategy:** Tenant isolation enforced at query level; ledger-only sourcing enforced by `ILedgerOnlyService` + CI `LedgerIsolationTests`; internal consistency verified by `IsBalanced`/`Variance`/`Reconciles` properties on each report DTO.
- **Audit Strategy:** No separate report audit store. The ledger itself (`JournalNumber`, `SourceType`, `SourceReference`, `JournalDate`, immutable lines) is the audit trail. Reports surface `GeneratedAtUtc` for freshness.
