# M4.5 PERFORMANCE REMEDIATION A1 — Tenant Authority Cache
## Eliminate per-request tenant-authority PostgreSQL re-proof
**Date:** 2026-09-25
**Scope:** Narrow production-path performance fix — ONE mechanism only (no publication caching, no JWT/blacklist/rate-limit/products/search/cart/Redis/Mongo/Npgsql/config/workload/diagnostic changes; `tests/load/k6/m4-realistic-mixed.js` untouched).

---

## 1. Root cause addressed

On the storefront pre-endpoint path, `TenantResolutionMiddleware` sequentially executes the
authenticated-tenant leg and then the request-tenant leg. Every leg that resolves a tenant id
re-proves the authority verdict (`IsActive && Status == Active && DeletedAtUtc == null`) with a
dedicated PostgreSQL `Tenants` query:

- `ResolveAuthenticatedTenantAsync` → `TenantAuthorityMemo.GetTenantByIdAsync` → PG.
- Domain-hit path → `ResolveTenantByIdAsync` → same memo → PG.
- Slug mapping hit → by-id authority PG (the mapping cache stores only the id, deliberately).
- Base-URL mapping hit → by-id authority PG.

`TenantAuthorityMemo` is per-`DbContext` (request-scoped), so it dedupes only *within* one request.
Across requests, every storefront hit costs ≥1 authority `Tenants` round-trip even when the tenant
mapping cache already knows the tenant. At 6000 VU this sequential pre-endpoint PG depth coincides
with Kestrel `queued_connections` (+4s), PgBouncer `cl_waiting` (+13s), first 503 (+29s), and
TenantRequestLeg p50 growth of ~9–49x vs the clean 3000-VU reference — with PG itself healthy
(active ≤ 11, max query age ~0.059s, no lock/IO waits) and the Npgsql client pool unexhausted.

This task removes exactly that per-request re-proof. Publication (`StorefrontPublicationGuardMiddleware`
/ `StorefrontPublicationStatusService`) is a separate later phase and was NOT changed.

## 3. Cache design

- **What is cached:** only *positively-authorized* verdicts — a detached copy of the `Tenant` row
  that passed the identical guards (`IsActive && Status == Active && DeletedAtUtc == null`) at load
  time. The cached value represents the same authority decision PostgreSQL gave; it is not a bare id.
- **What is never cached:** negatives. Missing/inactive/suspended/deleted/unknown tenants always
  fall through to PostgreSQL (fail-closed fresh; reactivation can never be locked out by a stale negative).
- **Key isolation:** `tenantauthority:<tenant-id>` — one key per tenant, cardinality O(active tenants),
  never O(requests). A verdict can only authorize the tenant it was loaded for.
- **TTL:** 60s absolute expiration, set only on PostgreSQL loads — hits never refresh it, so the
  absolute bound always holds. Deliberately much shorter than the 5-min mapping TTL because the
  verdict is security-adjacent; TTL is the backstop, post-commit eviction is primary.
- **Memory bound:** ≤1 small entry per tenant id, `CacheItemPriority.Low` (pressure-evicted first;
  eviction degrades to PG, never wrong). No Redis L2 (multiplexer already saturated — same rationale
  as the existing L1s).
- **Copy semantics:** copy-on-write into the cache and copy-on-read out of it, plus a scope-private
  copy per request memo entry — no scope can mutate another scope's verdict through a shared reference.
- **Stampede:** cold key → existing `KeyedSingleFlight` on the authority key (N concurrent cold
  requests = 1 PG load; followers share the detached result; failures evicted, never poisoned; no
  global locks; detached execution bounded by the DB command timeout; winner's scope kept alive by
  the owner's await — same pattern as the existing slug/base-URL gates).
- **Failure:** any cache failure (lookup/store/eviction) degrades to the direct PostgreSQL authority
  lookup — slower, never wrong. Unconfigured cache (test harnesses) behaves exactly as before.

## 4. Invalidation design

Reuses the existing tenant eviction infrastructure (`TenantResolutionInvalidationInterceptor`,
scoped, registered in the single `AddDbContext` options — all app scopes share it):

- **Trigger set (wider than mappings, deliberately):** EVERY `Tenant` Added/Modified/Deleted collects
  `entity.Id` pre-commit. No field-diffing: any committed mutation may change the verdict (lifecycle
  guards) or the snapshot payload consumed downstream (`Slug` is compared by the spoof check,
  `StorefrontBaseUrl`, `Name`).
- **Ordering:** collect pre-commit → evict post-commit (`SavedChanges`/`SavedChangesAsync`), evict-only,
  never publish, never fail the commit. Same drain as slug/base-URL eviction.
- **Gap analysis (no silent unsafe staleness):**
  - Searched production code for raw-SQL writes to `Tenants` (`ExecuteSql*` + `Tenants`): **none found**.
    All lifecycle writes (`TenantsController`, `TenantRegistrationService`, seed services) go through
    EF `SaveChanges` → interceptor. No rowversion/generation column exists on `Tenant`; none was needed.
  - Residual gaps, all TTL-bounded (60s) and logged: out-of-band DB edits (psql), eviction-callback
    failure, multi-replica convergence (M4.5 topology runs 1 replica).

## 5. Security / tenant-isolation review (final-diff pass)

- **Isolation:** per-tenant keys; cross-tenant and concurrent-isolation tests pass; deactivating A
  leaves B's warm verdict serving with 0 queries.
- **Stale authorization:** positives evicted post-commit on every tenant mutation + 60s absolute TTL
  never refreshed on hits; negatives uncacheable by construction. Deactivation/deletion/slug-change
  tests assert the entry is gone and the next request re-proves from PG (1 query) and is rejected.
- **Spoof/mismatch:** header-spoof (403) and auth-vs-request mismatch (403) blocks untouched and
  re-tested with warm authority entries; status codes and error bodies (`TENANT_REQUIRED`,
  `TENANT_FORBIDDEN`) unchanged.
- **Fail-closed:** unknown/malformed/empty ids → PG → existing 400 behavior; cache failure → PG.
- **Races:** per-key single-flight only; no locks across awaits; scope-private copies; follower
  cancellation collapses to the pre-existing abort semantics (cancelled token → immediate OCE, no query).
- **Poisoning:** L1 populated exclusively from guarded PG results; `SetAsync` rejects id mismatch/empty;
  keys are server-derived (claim/domain/mapping), never the raw inbound header.
- **Blast radius:** publication guard/service, JWT, blacklist, rate limiting, products, search, cart,
  Redis, Mongo, Npgsql/PgBouncer/PG config, diagnostics emission — all untouched (verified by diff;
  diagnostics suites 50/50 green).
