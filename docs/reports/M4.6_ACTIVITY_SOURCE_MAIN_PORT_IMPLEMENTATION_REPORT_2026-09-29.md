## Scope

This change ports the verified M4.5 Npgsql command `ActivitySource` lifetime fix into MAIN and integrates a production-safe diagnostics subsystem using MAIN's existing EF Core, dependency injection, request middleware, and OpenTelemetry architecture.

The implementation includes:

- One process-lifetime Npgsql command `ActivitySource` shared by all scoped interceptor instances.
- Scoped command and connection lifecycle interceptors, keeping mutable correlation state isolated per DI scope.
- Process-wide low-cardinality Npgsql and request metrics.
- Request-local Npgsql phase aggregation using `AsyncLocal` with deterministic scope restoration.
- Bounded, opt-in slow request and slow command logging.
- Validated configuration and explicit OpenTelemetry source/meter registration.
- Focused deterministic tests for behavior, ownership, lifetimes, concurrency, safety defaults, rate limiting, and MAIN wiring.

No database, migration, deployment, load test, browser, or external endpoint was used.

## MAIN Integration

`PointOfSale.API/Program.cs` now:

- Calls `AddNpgsqlDiagnostics(builder.Configuration)` exactly once.
- Resolves both diagnostics interceptors from the DbContext scope.
- Preserves the existing slow-query and domain interceptor registrations.
- Registers `NpgsqlDiagnosticsTelemetry.MeterName` with OpenTelemetry metrics.
- Registers the Npgsql and HTTP diagnostics activity sources with OpenTelemetry tracing.
- Places request lifecycle diagnostics after correlation ID middleware and before storefront cache policy middleware.

Service lifetimes are:

| Service | Lifetime |
| --- | --- |
| `NpgsqlDiagnosticsTelemetry` | Singleton |
| `RequestPhaseDiagnosticRateLimiter` | Singleton |
| `NpgsqlDiagnosticLogRateLimiter` | Singleton |
| `NpgsqlLifecycleDiagnosticInterceptor` | Scoped |
| `NpgsqlConnectionLifecycleDiagnosticInterceptor` | Scoped |

The singleton telemetry service owns the process-wide `Meter`. Scoped interceptors do not own or dispose the shared static `ActivitySource`.

## Configuration

All settings are optional. Defaults are intentionally conservative.

| Setting | Default | Behavior |
| --- | --- | --- |
| `NpgsqlDiagnostics:Enabled` | `true` | Enables Npgsql activities and metrics |
| `NpgsqlDiagnostics:SlowCommandLoggingEnabled` | `false` | Enables bounded slow-command records |
| `NpgsqlDiagnostics:CaptureCommandTextInActivities` | `false` | Allows truncated command text in spans when explicitly accepted |
| `NpgsqlDiagnostics:CaptureConnectionIdentityInActivities` | `false` | Allows connection identity in spans when explicitly accepted |
| `NpgsqlDiagnostics:SlowCommandThresholdMs` | `2000` | Slow-command threshold |
| `NpgsqlDiagnostics:MaxStatementLength` | `500` | Maximum opt-in command text length |
| `NpgsqlDiagnostics:MaxSlowCommandLogsPerSecond` | `10` | Process-wide command log bound |
| `RequestPhaseDiagnostics:Enabled` | `false` | Enables bounded slow-request records |
| `RequestPhaseDiagnostics:SlowRequestThresholdMs` | `2000` | Slow-request threshold |
| `RequestPhaseDiagnostics:MaxRecordsPerSecond` | `10` | Process-wide request log bound |

Threshold, length, and rate settings are validated on startup.

## Security And Cardinality Review

- Metrics have no tenant, user, route, command, connection, or other dimensions.
- Request logs contain route templates rather than query strings or path values.
- Request logging never records request bodies, query strings, authorization headers, cookies, tenant IDs, or user IDs.
- Slow-command logs record duration, operation class, and error state only.
- Connection failure logs record duration and exception type, not exception messages or exception objects.
- Raw SQL and connection identity activity tags are disabled by default and require explicit configuration.
- Command failure activities carry an error status without exception messages.
- Rate limiters bound optional detailed logs process-wide.
- Request state is isolated with `AsyncLocal`; disposal restores any previous context.
- Telemetry counters use interlocked updates and do not decrement below zero.

No credential, connection string, token, or tenant-specific value was added to source, configuration, logs, or metric labels.

## Limitations

- Focused deterministic tests use EF Core diagnostic event objects and do not open a live PostgreSQL connection.
- A full repository test run was not performed because the task required database-free focused verification and the wider suite contains environment-dependent coverage.
- Runtime exporter delivery and production sampling behavior were not exercised against an external collector.
- Provider-internal pool statistics are not inspected. The active connection gauge reflects connections observed through instrumented DbContexts; idle connections remain zero unless a future public provider signal supplies them.
- EF materialization timing is an approximation based on reader consumption because no stable public EF Core hook exposes the complete materialization subsegment.
- The opt-in command text tag truncates but does not redact SQL literals. It must remain disabled unless the deployment accepts that data classification.
