CRITICAL ISSUE DISCOVERED:
==========================

Error: "Invalid Guid Pattern" during Elasticsearch deserialization

ROOT CAUSE:
-----------
When we added the `tenantId` field to existing Elasticsearch documents,
Elasticsearch auto-mapped it as 'text' instead of 'keyword'.

The C# code expects `tenantId` to be a 'keyword' field (for Guid deserialization),
but Elasticsearch stored it as 'text', causing the NEST client to fail when
trying to deserialize the text value as a Guid.

TECHNICAL DETAILS:
------------------
1. PublicAffiliateProductSearchDocument.cs defines:
   [Keyword]
   public Guid TenantId { get; set; }

2. When index is created via AutoMap(), NEST respects [Keyword] attribute

3. BUT: Index was created BEFORE we added TenantId field

4. When we updated existing documents with tenantId, Elasticsearch
   auto-mapped it as 'text' (default for unknown string fields)

5. NEST client tried to deserialize 'text' field as Guid → FAIL

=====================
