# Affiliate System Bug Fixes & Improvements Summary

## 0. Problem: Affiliate Analytics Crash (`System.InvalidOperationException`)
**Issue:**
When trying to load dashboard data, the `AffiliateAnalyticsController` threw an `InvalidOperationException` due to a LINQ translation error. It was attempting to filter affiliate accounts using the `IsActive` property, which is a computed C# property and not directly mapped to a column in the PostgreSQL database.

**Solution:**
* **Backend (`AffiliateAnalyticsController.cs`):** We replaced the usage of the computed `.IsActive` property with its underlying database-mapped condition: `.Status == AffiliateStatus.Active`. This allowed Entity Framework Core to correctly translate the query into SQL, restoring full functionality to the affiliate analytics dashboard and preventing server crashes.

---

## 1. Problem: The Affiliate Link `/login` Redirect Loop
**Issue:**
When an affiliate generated a link and tried to visit it, the system would immediately redirect them to the POS Admin `/login` page instead of displaying the correct product or portal.

**Root Cause:**
* **Polluted API Instance:** `affiliateApi.js` was mistakenly importing and using the global POS `api.js` Axios instance. 
* **Missing Token & Headers:** Because it used the POS instance, the request lacked the `affiliate_accessToken` and the required `X-Tenant-Id` header.
* **Aggressive Interceptor:** The backend rightly returned a `401 Unauthorized` for the discovery API, which triggered the POS `api` response interceptor to aggressively force a redirect to `/login`.

**Solution:**
* We heavily refactored `affiliateApi.js` to strictly import and use `affiliateAxios` (from `affiliateAuthApi.js`). This completely decoupled the Affiliate Portal's network traffic from the POS Admin's network traffic and ensured the correct tokens and headers were sent.

---

## 2. Problem: Missing `TenantId` Storage for Multi-Tenancy
**Issue:**
Even with the correct Axios instance, the backend's Affiliate endpoints require an `X-Tenant-Id` header to securely scope data to a specific store. However, the affiliate frontend was never being handed the `TenantId` upon logging in.

**Solution:**
* **Backend (`AffiliateAuthController.cs`):** We modified the C# `AffiliateAuthResponse` DTO and the corresponding registration, login, and token refresh endpoints to resolve and include the `TenantId` property alongside the authorization token.
* **Frontend (`affiliateAuthApi.js`):** We updated the `register` and `login` methods to capture `tenantId` from the backend's auth response and securely store it in `localStorage.setItem(STORAGE_KEYS.TENANT_ID, result.tenantId)`.

---

## 3. Problem: Invalid "Copy Affiliate Link" Generation
**Issue:**
The URL generated by the "Copy Affiliate Link" button was fundamentally broken for three reasons:
1. It pointed to `window.location.origin` (Port `5173`), which is the internal POS Admin interface space, not the public facing store.
2. It lacked the Subdomain Context (`storeSlug.domain.com`), which is the cornerstone of how the Storefront inherently identifies which store is being accessed.
3. The routing path was mapped to `/product/` instead of the Storefront's configured `/products/`.

**Solution:**
* We updated `copyAffiliateLink` inside `AffiliatePortal.jsx` to dynamically build a production-grade external link:
  * It reads `import.meta.env.VITE_STOREFRONT_DOMAIN` (Defaulting to `localhost:5174`).
  * It dynamically retrieves `affiliate_storeSlug` from local storage (e.g., `anatico`).
  * It accurately prepends the slug as a subdomain (yielding `anatico.localhost:5174`).
  * It fixes the path syntax to hit `/products/:slug` (the correct react-router path).

---

## 4. Problem: Local Subdomain Resolution ("Store Not Found")
**Issue:**
After generating the perfect link (`http://anatico.localhost:5174/...`), clicking it caused the front-end Storefront system to throw a "Store Not Found" error. This happened because Windows doesn't inherently know how to map a local subdomain (`anatico.localhost`) back to your local development machine loopback address (`127.0.0.1`), causing the Storefront's `tenantResolver.ts` to falsely conclude the store didn't exist.

**Solution:**
* We triggered an elevated PowerShell command script (requesting UAC Admin privileges) to deliberately append `127.0.0.1 anatico.localhost` to your native Windows `C:\Windows\System32\drivers\etc\hosts` file, officially routing your local DNS to work seamlessly with multi-tenant storefront domains.

---

## Conclusion
The **Affiliate System** is completely dependent on the **Storefront System** for traffic realization.
* **The Affiliate Portal (Port `5173`):** Is purely an isolated B2B administrative dashboard for promoters to fetch their referral codes, view statistics, and discover products.
* **The Storefront (Port `5174`):** Is the primary B2C e-commerce engine. Without it successfully running and resolving the tenant subdomains, an affiliate link simply routes into a void, breaking the affiliate attrition cycle.
