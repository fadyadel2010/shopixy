## Root Cause And Timestamp Provenance

- `RedisJsonCacheService.ShouldBypassForProjectionLag` compared `ProjectionLastUpdatedAtUtc` to `SourceEventOccurredAtUtc` and bypassed cache when the delta exceeded the configured 45-second threshold - **CODE-PROVEN**.
- `ProductDocument.LastEventOccurredAtUtc` is the source business event timestamp of the newest product-level event applied to the Mongo product projection - **CODE-PROVEN**.
- `ProductDocument.SyncedAtUtc` is projection/write processing time at ingestion, but `ProductSearchSqlAuthorityOverlay.ApplyAsync` and `ApplyBatchAsync` restamp it with `DateTime.UtcNow`/`nowUtc` during read-side SQL authority recomposition - **CODE-PROVEN**.
- `ProductDocument.LastEventVersion` records the newest product-level event version applied to the Mongo projection - **CODE-PROVEN**.
- `ProductDocument.ProductGeneration` is copied from SQL `Product.ProjectionMutationVersion`, which is the current source aggregate revision - **CODE-PROVEN**.
- The previous guard compared processing/recomposition time to business event time. Those timestamps do not represent compatible events after SQL overlay restamping - **CODE-PROVEN**.
- A seeded product with an old source event and a current projection could be rejected because `SyncedAtUtc - LastEventOccurredAtUtc` measured source event age, not projection lag - **CODE-PROVEN**.

## Code Correction

- Added optional `ProjectionVersion` and `SourceVersion` fields to `CacheEnvelope<T>` and `CachePopulationResult<T>` - **CODE-PROVEN**.
- Added `CacheProjectionFreshnessGuard.ShouldBypass(...)`; when revision proof exists, it bypasses only when proof is incomplete or `ProjectionVersion < SourceVersion`; otherwise existing timestamp fallback remains unchanged - **CODE-PROVEN**.
- Updated Redis read and population guards to pass and evaluate revision proof while preserving cache keys, TTLs, invalidation generation fencing, single-flight behavior, and the existing timestamp fallback for non-revision callers - **CODE-PROVEN**.
- Updated `StorefrontProductService.GetProductListAsync` to compute product-list freshness from SQL-recomposed documents by comparing each visible product's `LastEventVersion` against SQL `ProductGeneration` converted through `ProductEventVersionHelper` - **CODE-PROVEN**.
- Product-list cache population now fails closed if any visible product lacks event/revision proof or if any visible product's source generation is ahead of the applied projection version - **CODE-PROVEN**.
- Restored the explicit `cacheFactoryExecuted` sentinel expected by existing architecture certification for avoiding duplicate SQL recomposition on a cache miss - **TEST-PROVEN**.
