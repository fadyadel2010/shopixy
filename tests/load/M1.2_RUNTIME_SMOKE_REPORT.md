## 11. Failures/blockers

1. **(Env) `GET /health/ready` → 503.** Cause: single entry
   `payout_external_truth_readiness: Unhealthy`
   (`LatestReconciliationStatus=Critical`, `MismatchCount=1`); all other
   entries (postgres/redis/mongo/ES/RabbitMQ/bus/outboxes) Healthy. Readiness
   gate, not an SUT-down signal — 6/7 catalog reads still returned 200.
   Verdict: FAIL at endpoint level, environment-owned, not harness-owned.
   Do not “fix” by weakening the smoke check; M2 should treat health as an
   informational gate with its own assertion.
2. **(Harness, corrected) bare `localhost:5010` Host → `400
   TENANT_REQUIRED` on all storefront reads.** Cause (code-verified):
   `TenantResolutionMiddleware` strips inbound `X-Tenant-Id` and resolves via
   claim/domain/verified-host/`UrlTemplate`; `TryExtractTenantSlug` requires
   the Host port to equal the template port (5174) when non-default
   (`TenantResolutionMiddleware.cs:380`). All tenants have
   `StorefrontBaseUrl=NULL`, so only the template path works, requiring
   `Host: {slug}.localhost:5174`. Verified: `Host: ahramstore.localhost:5174`
   → 200 with real catalog data. Correction (harness-only, in
   `tests/load/`): `http.js` accepts `hostOverride`; `smoke.js` defaults it
   to `{TEST_SLUG}.localhost:5174` (overridable via `TEST_HOST_OVERRIDE`);
   README documents it. Verdict: corrected and re-validated (6/8 → 200s).
3. **(Harness fixture) `resolve-slug/ahramstore` → 404.** Correct-negative:
   `ahramstore` is a tenant slug, not a catalog (product/category) slug, so
   the resolver has nothing to return. I-2 therefore stays vacuous (§8).
   No route was substituted. M2 fix: dedicated catalog-slug input from the
   seed manifest. Verdict: FAIL at endpoint level, harness-fixture-owned.
4. **No blockers for M2 planning.** k6 installed, preflight proven both
   directions, tenant context mechanism understood and working.

   `tenant-a/b/c` or adopt `AhramStore` as Tenant-A; mandatory

   an environment entry criterion for perf runs.
4. Add post-run read-only spot-checks (outbox depth, reservation count,
   stock levels) to turn §10’s client-side proof into server-side proof.
5. Keep local Windows runs as validation-only; capacity stages stay gated on
   the K8s/perf environment with exporters (discovery §14).
6. Do **not** declare production capacity or full tenant-isolation
   certification from this smoke: I-1 ran without sentinels, I-2 was
   vacuous, and concurrency was 1 VU by design.
